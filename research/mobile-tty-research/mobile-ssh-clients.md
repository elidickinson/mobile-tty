# Research: mobile ssh clients

Scope: notes on mobile terminal/SSH client UX, gathered for mobile-tty (web-based TUI terminal for iPhone). Depth on Termux (Android), Blink Shell (iOS), a-Shell (iOS), OpenTerm (iOS). Shallow coverage of Termius, Shelly (via Blink sibling forks), Mosh-as-client.

## Termux extra-keys row

- The extra-keys row is configured in `~/.termux/termux.properties` via the `extra-keys` property, parsed as a nested JSON-ish list of rows. Default is a **double row**: `[['ESC','/',{key: '-', popup: '|'},'HOME','UP','END','PGUP'], ['TAB','CTRL','ALT','LEFT','DOWN','RIGHT','PGDN']]`. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/settings/properties/TermuxPropertyConstants.java)
- Each key entry is either a string (`'ESC'`) or an object `{key: X, popup: Y}` where popup can be another key name **or a macro object** `{macro: "CTRL f d", display: "tmux exit"}`. Macros are space-separated sequences of modifier names (`CTRL`, `ALT`, `SHIFT`, `FN`) followed by a key name or arbitrary literal text; `\n` in a macro executes (sends Enter). [source](https://raw.githubusercontent.com/termux/termux-tools/master/termux.properties) and [source](https://www.reddit.com/r/termux/comments/1c4p2au/extra_keys_macro_note/)
- Special modifier buttons (`CTRL`, `ALT`, `SHIFT`, `FN`) are **toggle-based special buttons**, each with 3 states: inactive / active (one-shot) / locked. `SpecialButtonState` tracks `isActive` and `isLocked`. Tap toggles `isActive`; when a key event is consumed via `readSpecialButton(SpecialButton, autoSetInActive=true)`, the modifier auto-clears unless `isLocked`. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysView.java)
- **Long-press on a special button locks it**: `SpecialButtonsLongHoldRunnable` (fired after `mLongPressTimeout`) sets `isLocked = !isActive; isActive = !isActive` — i.e. long-press transitions the modifier into a sticky-locked state. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysView.java)
- **Auto-repeat on long-press** is implemented for a specific key list only: `PRIMARY_REPETITIVE_KEYS = UP, DOWN, LEFT, RIGHT, BKSP, DEL, PGUP, PGDN`. Uses `scheduleWithFixedDelay` with initial delay `mLongPressTimeout` (system long-press timeout, default ~400ms, clamped to 200–3000ms) and repeat delay `DEFAULT_LONG_PRESS_REPEAT_DELAY = 80ms` (5–2000ms range). [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysView.java) and [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysConstants.java)
- **Popup keys are triggered by swipe-up, not long-press**: in the `OnTouchListener`, on `ACTION_MOVE` with `buttonInfo.getPopup() != null`, if `event.getY() < 0` (finger above the button top edge) a `PopupWindow` shows the popup key; if finger comes back down (`Y > 0`) popup is dismissed. Releasing inside the popup fires the popup's click. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysView.java)
- Key display can be styled via `extra-keys-style` property with presets `default`, `arrows-only`, `arrows-all`, `all`, `none` — these swap display glyphs (← → ↑ ↓ ⎋ ⌫ ⌦ ⇱ ⇲ ⇑ ⇓ ⎈ ⎇) without changing key identity. `extra-keys-text-all-caps` (default true) forces labels uppercase. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysConstants.java) and [source](https://raw.githubusercontent.com/termux/termux-tools/master/termux.properties)
- Aliases exist in config parsing: e.g. `CONTROL`→`CTRL`, `SHFT`→`SHIFT`, `PAGE_UP`/`PAGEUP`/`PAGE UP`/`PAGE-UP`→`PGUP`, `LT`/`RT`/`DN`→arrows, `BACKSLASH`→`\`, `APOSTROPHE`→`'`. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/extrakeys/ExtraKeysConstants.java)
- Terminal-side dispatch: known key names go through `PRIMARY_KEY_CODES_FOR_STRINGS` and are injected as Android `KeyEvent`s with meta state; non-known strings are sent per-codepoint via `mTerminalView.inputCodePoint(...)`. Macros iterate words: modifier keywords accumulate `ctrlDown/altDown/...` flags, next non-modifier word consumes them. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/terminal/io/TerminalExtraKeys.java)

## Termux text input, IME, gestures, selection, URL handling

- TerminalView creates an `InputConnection` with `inputType = InputType.TYPE_NULL` ("the most correct input type and avoids issues with other hacks"); alternatively when `enforce-char-based-input=true` it uses `TYPE_TEXT_VARIATION_VISIBLE_PASSWORD | TYPE_TEXT_FLAG_NO_SUGGESTIONS` — the canonical trick for **suppressing autocorrect/suggestions** on soft keyboards. [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- `\n` from IME commitText is rewritten to `\r` because "AOSP keyboard and descendants send `\n` as text when the enter key is pressed... a terminal expects `\r`". Certain control codes from penti-style keyboards (codepoints 28–31) are remapped to `\`, `]`, `^`, `_` with `ctrlHeld=true`. [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- `enforce-char-based-input` exists because "Some keyboards seems do not reset the internal state on TYPE_NULL. Affects mostly Samsung stock keyboards" (issue #686). `ctrl-space-workaround` exists because ctrl+space does not work on some ROMs. [source](https://raw.githubusercontent.com/termux/termux-tools/master/termux.properties) and [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- Terminal-view gestures (custom `GestureAndScaleRecognizer`): single tap → `mClient.onSingleTapUp` (request focus / show keyboard); long press → `startTextSelectionMode` + haptic; scroll → row-granular scrollback with remainder tracking (`mScrollRemainder`) so small drags accumulate; pinch → `onScale` (font scaling); fling → momentum via `Scroller` with `SCALE = 0.25` damping. Double tap is deliberately a no-op ("may be followed by zoom"). [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- Text selection: `TextSelectionCursorController` provides selection handles, multi-line selection, and a context menu with copy/paste. Long-press enters selection mode; selection auto-aborts if scrolling pushes it past the transcript edge ("unless we're hitting the end of history transcript, in which case we abort text selection and scroll to end"). [source](https://deepwiki.com/termux/termux-app/4.1-terminalview) and [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- URL tap-to-open is opt-in via `terminal-onclick-url-open` (`KEY_TERMINAL_ONCLICK_URL_OPEN`, **default false** in `TERMUX_DEFAULT_FALSE_BOOLEAN_BEHAVIOUR_PROPERTIES_LIST`). When enabled, links in the transcript open on single tap. [source](https://raw.githubusercontent.com/termux/termux-app/master/termux-shared/src/main/java/com/termux/shared/termux/settings/properties/TermuxPropertyConstants.java)
- Scrollback size is `terminal-transcript-rows` (default 2000, max 50000 per wiki comment in sample properties). `back-key = escape` makes Android back send ESC. `volume-keys = virtual` (default) makes volume keys act as modifier input. `shortcut.create-session = ctrl + t` etc. [source](https://raw.githubusercontent.com/termux/termux-tools/master/termux.properties)
- Bell behavior is user-set: `bell-character = vibrate | beep | ignore` (default vibrate). [source](https://raw.githubusercontent.com/termux/termux-tools/master/termux.properties)

## Blink Smart Keys (iOS, soft keyboard accessory)

- Smart Keys bar appears **only when the on-screen keyboard is visible** and hidden for external keyboards. Contents: modifiers `CTRL ^`, `ALT ⌥`, `ESC ⎋`, arrow keys, function/alternate cursor keys (Home/End/PgUp/PgDn when pressing CMD), and a **scrollable center area** with more keys. [source](https://docs.blink.sh/)
- Modifier buttons are **tap-toggle** (single tap → toggle `selected`), with a separate `UILongPressGestureRecognizer` at 0.3s minimum that enables "hold to chain": while long-press is held, `isLongPress = YES` — and in `-[SmartKeysView modifiers]`, modifiers only auto-release (`_ctrlButton.selected = NO`) if `!isLongPress`. So tap = one-shot, long-press-hold = chained manual release. Doc states "Hold a modifier to chain multiple combinations, useful in applications like Emacs where you use chains like `C-x`, `C-c`." [source](https://raw.githubusercontent.com/blinksh/blink/main/Frameworks/SmartKeys/smartkeys/SmartKeysView.m) and [source](https://docs.blink.sh/)
- Selecting ALT swaps the non-modifier key section to an alternate set (F-keys / cursor keys): KVO on `_altButton.selected` calls `showNonModifierKeySection:SKNonModifierButtonTypeAlternate` when ALT becomes active. [source](https://raw.githubusercontent.com/blinksh/blink/main/Frameworks/SmartKeys/smartkeys/SmartKeysView.m)

## Blink gestures, selection, display fitting

- Touchscreen gestures listed in docs: two-finger tap → new shell; side-to-side swipe → switch shells; pinch → adjust terminal size (font scale); **tap and drag → start selection mode**. Selections can be dragged to other apps, and from other apps into Blink (pasted at cursor). Double-tapping the **iOS Home Bar** (or pressing `CMD` twice) shows the Context bar (tabs, Snips, Lock/Geo toggle). [source](https://docs.blink.sh/)
- Three-finger tap brings a display-fit menu with **Cover (edge to edge), Fill (space top/bottom), Fit (5pt inset all sides)** — a user-facing gesture for adjusting terminal viewport padding. [source](https://docs.blink.sh/basics/tips-and-tricks)
- Pasteboard: recent versions have "Copy Raw" via Cmd-Shift-C; fixed terminal copy adding trailing EOL whitespace; fixed single-CJK-char copy selection. UNCERTAIN: exact version containing those fixes — cited in App Store "what's new" text without version number in fetched page. [source](https://apps.apple.com/gb/app/blink-shell-build-code/id1594898306)
- Inline images via iTerm2 `imgcat` escape sequences over SSH are supported (not through mosh/tmux/screen). [source](https://docs.blink.sh/basics/tips-and-tricks)

## Blink keyboard remapping & external keyboards

- Keyboard config distinguishes: Blink Shortcuts (app-level: open terminal, copy/paste), Custom Keyboards (disable iOS third-party soft keyboards inside Blink), Modifiers (remap any modifier incl. Caps Lock → Ctrl/Esc; left and right side of same modifier can be assigned differently; can send a "key press" instead of a modifier so e.g. Caps-press = Esc, Caps-combo = Ctrl), and Custom presses (remap single key presses into arbitrary sequences — example given: making ctrl-space actually send ctrl-space instead of triggering iPadOS emoji switcher). [source](https://docs.blink.sh/basics/customize)
- "Same for both sides" toggle off allows e.g. left Option = Meta, right Option = Alt. Emacs use case: Alt→Meta via "Press send: None, As modifier: ESC". [source](https://docs.blink.sh/basics/tips-and-tricks)
- The on-screen keyboard includes a CMD key so all hardware-keyboard shortcuts are available from touch. [source](https://docs.blink.sh/basics/customize)

## Blink sessions, Mosh, reconnect behavior

- Blink is built around Mosh: "Mosh, SSH and CLI tools. Mosh was built for constant mobile connectivity." App Store claims "Mosh connections that even survive a device reboot" (user-facing claim; mechanism not described in fetched docs). [source](https://blink.sh/) and [source](https://apps.apple.com/us/app/blink-shell-build-code/id1594898306)
- Mosh: UDP-based SSP, port range 60000-61000 recommended open on server; auth via SSH then Mosh takes over; predictive local echo reduces perceived latency. **Mosh has no native scrollback** — Blink's official answer: "Mosh does not support scroll, due to it only dumping changes between screens, like video rendering protocols... we recommend pairing it with a terminal multiplexer like Tmux or Screen." [source](https://docs.blink.sh/advanced/advanced-mosh) and [source](https://github.com/blinksh/blink/discussions/1933)
- Blink supports Mosh features beyond stock: "additional support for new Mosh features like TrueColor rendering and remote clipboard" (requires newer mosh on server). [source](https://docs.blink.sh/advanced/advanced-mosh)
- Common reconnect pattern documented: per-host startup command like `tmux a -t session_name` or `screen -rd session_name`, or `mosh host -- tmux a -t session_name`. [source](https://docs.blink.sh/basics/tips-and-tricks)

## a-Shell (iOS) — hterm-based, gesture-rich

- a-Shell renders via **hterm in a WKWebView** (`hterm.html`, `script.js`), with gesture handling in a separate `gestures.js`. Interface = WKWebView + Swift shell. UNCERTAIN (terminology): DeepWiki calls it a "terminal in a WKWebView" — consistent with the listed `hterm.html`/`gestures.js` sources. [source](https://deepwiki.com/holzschu/a-shell/7.1-getting-started)
- Configurable swipe-to-key mapping: `gestures_.preferences.swipeLeft = {2: '\x1b'}` (two-finger left swipe sends ESC), `swipeRight = {2: '\t'}` (two-finger right swipe sends Tab). Gesture sending goes through `term_.io.sendString(key)`. Three-finger right → Enter was considered but commented out as broken. [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- One-finger horizontal drag moves the cursor by sending arrow-key escapes (`\x1b[D`/`\x1b[C`, or `\x1bO` prefix in application-cursor mode); the gesture code tracks character-grid deltas and emits one escape per character crossed. Horizontal drags are suppressed when `less`/`man`/`perldoc` is detected running (`isLessRunning` regex on `window.commandRunning`). [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- One-finger vertical drag: if alternate screen active (or 2 fingers), moves cursor (inverted under `less` for natural scrolling); otherwise scrolls hterm scrollback line-by-line via `term_.scrollLineUp()/Down()`. [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- **Inertial scrolling is implemented in JS**: `VelocityTracker` per pointer, decay factor `INERTIAL_SCROLL_DECAY_FACTOR = 0.1` per second, min start speeds 40 chars/s (X) and 15 chars/s (Y), initial velocity multiplier 1.4×, max 2000 lines/s; during inertia, arrow-key escape injection continues (`onInertialScrollUpdate`) unless `allowNonarrowKeys` forbids it. Same momentum loop also drives mouse-wheel gestures (`MOUSE_WHEEL_GESTURE_MAX_SPEED = 80` l/s). [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- Gesture disambiguation: gestures "snap" to horizontal or vertical; breakaway thresholds `SNAP_BREAKAWAY_HORIZ_CHARS = 6` / `SNAP_BREAKAWAY_VERT_CHARS = 4`; horizontal runs need ≥ 7 chars (`HORIZ_KEYBOARD_KEYPRESS_CHARS`) to register as a keypress gesture. hterm's own touch scrolling is deliberately monkey-patched off (`disableHtermTouchScrolling`) once vertical motion exceeds 0.5 char. [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- Debug overlay: a `gestureStatus` div (fixed, bottom-right, translucent) shows live gesture state, gated on a `DEBUG` const, and posts `showDebugMsg:` to the native side via `window.webkit.messageHandlers.aShell.postMessage` — an on-device diagnostics pattern. [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- Toolbar: shown when the keyboard appears; buttons for ESC/Tab/arrows; toggle via `showToolbar`/`hideToolbar` shell commands; **customizable via a config file created by `config -t`** (`config --toolbar`: "Create a configuration file to customize the toolbar"). [source](https://deepwiki.com/holzschu/a-shell/7.1-getting-started)
- Hardware shortcuts: Cmd-K clear, Cmd-N new window, Cmd-W close, Cmd-X cut, Cmd +/- font size, Cmd-A select all, Ctrl-C interrupt, Ctrl-D EOF. iOS Settings bundle has a **Caps-Lock = Escape** toggle. [source](https://deepwiki.com/holzschu/a-shell/7.1-getting-started)
- Session restore: a-Shell saves terminal text content + currently-running command and restores both on relaunch (`window.commandRunning` restores). Issue #68 documents a bug where a session with very large output (e.g. full `pacman -Syu` log) failed to save the current command, causing an exited `ssh` to be restarted on app reopen; maintainer's response was to reverse the save order (command first, text second) and clamp saved text size. [source](https://github.com/holzschu/a-shell/issues/68)
- App-setting "Content preservation between sessions" exists in the iOS Settings bundle. [source](https://deepwiki.com/holzschu/a-shell/7.1-getting-started)

## OpenTerm (iOS, louisdh) — autocomplete driven by history + InputAssistant

- Architecture: a single `TerminalTextView` (UITextView subclass) shows everything — output and editable command on one canvas; `currentCommandStartIndex` splits "current command" from transcript; the "current command" is rewritten in place. No terminal grid; command is a text-editing session. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/View/TerminalView.swift)
- Autocomplete **uses `InputAssistantView` (the InputAssistant library's above-keyboard bar)** attached as the text view's input accessory; an `AutoCompleteManager` supplies suggestions. States: `.empty(commands)` → shows all commands matching prefix; `.command(program, arguments, completions)` → per-program argument completions; `.executing(completions)` → suggestions while a command runs. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/Data/AutoComplete/AutoCompleteManager.swift) and repo tree (`OpenTerm/Data/AutoComplete/AutoCompleteManager+InputAssistant.swift`)
- Completions are derived from **command history** (HistoryManager) plus available commands; a ghost-text **inline auto-completion suffix** is rendered into the text view itself (`textView.autoCompletion = " (description)"` / completion string) — i.e., Fish-style autosuggestion filled by the first candidate, plus tappable bar suggestions from InputAssistant. Tab key (hardware) accepts first completion via `UIKeyCommand(input: "\t")`. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/View/TerminalView.swift)
- Hardware key commands: Cmd-K clear buffer, Ctrl-C stop, Ctrl-A/Ctrl-E beginning/end of line (implemented by moving the selected range within the text view), Tab complete. No custom ESC key on soft keyboard — OpenTerm is a local shell without SSH-style modifiers as focus. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/View/TerminalView.swift)
- File/URL integration: output parser annotates file paths as tappable links (`withFilesAsLinks(currentDirectory:)`); drag-and-drop of text out of the terminal creates a `UIDragItem` with file-URL representation; drag-in pastes at cursor. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/View/TerminalView.swift)
- Keyboard occlusion handled via a `KeyboardObserver` util adjusting `textView.contentInset.bottom` to the intersecting keyboard frame height (minus safe area), animated with the keyboard's own duration/curve. [source](https://raw.githubusercontent.com/louisdh/openterm/master/OpenTerm/View/TerminalView.swift)
- Repo archived 2018-06; 1651 stars, still on the App Store as of research date. [source](https://github.com/louisdh/openterm)

## Termius (closed source, public docs)

- Android "extended keyboard" is split into three sections: left = gesture button (toggles terminal touch behavior mode), middle = horizontally sliding special-keys row, right = `display keyboard` and `more` buttons. Special-key groups can be **reordered (drag handles), deleted, and user-created** from a "Manage shortcuts" settings panel. [source](https://github.com/smanask/Termius-Documentation/blob/master/android/features/extended_keyboard.md)
- Extended keyboard extra buttons include: Autocomplete toggle ("Toggle on to predict/suggest input"), Paste password, Snippets panel, SFTP panel. [source](https://github.com/smanask/Termius-Documentation/blob/master/android/features/extended_keyboard.md)
- Marketing description: "Use gestures or shake the device while in the terminal to emulate stroking of Tab, arrows, PgUp/Down, Home" — i.e. shaking the device maps to special keys. [source](https://play.google.com/store/apps/details?id=com.server.auditor.ssh.client)
- iOS touch terminal blog post (Jul 2024) notes the special-key list is user-customizable. [source](https://termius.com/blog/new-touch-terminal-on-ios)
- Supports SSH, Mosh, Telnet, SFTP on free tier. [source](https://apps.apple.com/us/app/termius-modern-ssh-client/id549039908)

## Mosh-as-client patterns (applies across apps)

- Mosh's UDP + state-synchronization design means **local scrollback is fundamentally unavailable**: "mosh by default doesn't support native scrollback. The way mosh is implemented (by default at least) is to just paint the screen locally". Standard workaround everywhere: run tmux/screen on the server. [source](https://news.ycombinator.com/item?id=21641125)
- tmux-over-mosh scrollback has its own wrinkle: with `set -g mouse on`, swipe-to-scroll can be relayed as mouse events; multiple reports say mouse wheel scrolling over mosh+tmux behaves unexpectedly vs tmux over ssh. UNCERTAIN/CONFLICTING: [ghostty discussion](https://github.com/ghostty-org/ghostty/discussions/4617) (scrollback broken over mosh+tmux) vs [getmoshi.app](https://getmoshi.app/articles/fix-mosh-scrollback) (claims `set -g mouse on` + swipe works).
- Third-party patch exists for mosh local scrollback ("you must build mosh from source, scrolling is less fluid than native, and click-drag is relayed, so you must hold Option"). [source](https://unix.stackexchange.com/questions/145181/use-mosh-without-giving-up-local-scrollback-history)

## Diagnostics / debugging approaches observed

- a-Shell: on-screen `gestureStatus` debug div + `webkit.messageHandlers` bridge to native side for live logging from the JS layer. [source](https://raw.githubusercontent.com/holzschu/a-shell/master/gestures.js)
- Termux: `TERMINAL_VIEW_KEY_LOGGING_ENABLED` static flag on TerminalView — when set, every IME event (`commitText`, `deleteSurroundingText`, `finishComposingText`) is logged via `mClient.logInfo(LOG_TAG, ...)`; "Log terminal view key and IME events." [source](https://raw.githubusercontent.com/termux/termux-app/master/terminal-view/src/main/java/com/termux/view/TerminalView.java)
- Termux app-level: `ReportActivity` for crash/error display in markdown, plus a dedicated `ReportActivityBroadcastReceiver`; issues flow to GitHub issue tracker. [source](https://deepwiki.com/termux/termux-app/3.4-android-manifest)
- Blink: on crash, developer receives crash reports; docs explicitly beg users not to report issues via App Store reviews but via GitHub Discussions. No on-device debug console documented. [source](https://docs.blink.sh/)
